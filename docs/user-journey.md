# User Journey: อีคอมเมิร์ซ — Marketplace: ค้นหาและสั่งซื้อสินค้า

คัดลอกจากเอกสาร User Journey หลัก (ระบบที่ 2/24) ใช้เป็นข้อมูลอ้างอิงสำหรับ prompt AI ในแต่ละสัปดาห์

## Persona
**"พี่เอ"** อายุ 35 ปี แม่บ้าน ซื้อของใช้ในบ้านผ่านมือถือเป็นประจำ เปรียบเทียบราคาก่อนตัดสินใจซื้อทุกครั้ง

## เป้าหมาย
หาสินค้าที่ต้องการในราคาดีที่สุด สั่งซื้อและชำระเงินได้อย่างมั่นใจ

## Pain Points
- สินค้าปลอมหรือไม่ตรงปก ไม่รู้จะเชื่อร้านไหน
- ค่าส่งไม่ชัดเจนจนกว่าจะถึงหน้าชำระเงิน
- โปรโมชั่น/คูปองใช้ไม่ได้ตอนเช็คเอาท์
- ไม่รู้สถานะพัสดุว่าถึงไหนแล้ว

## ขั้นตอน (User Journey) — ทำใน Week 1
| ขั้นตอน | หน้าจอ / Touchpoint | การกระทำของผู้ใช้ | การตอบสนองของระบบ | ไฟล์ที่สร้าง |
|---|---|---|---|---|
| 1 | หน้าค้นหา | พิมพ์คำค้นหาสินค้า | แสดงผลพร้อม filter | `frontend/index.html` |
| 2 | หน้ารายการสินค้า | เปรียบเทียบราคา/รีวิวหลายร้าน | จัดอันดับตาม relevance | `frontend/index.html` |
| 3 | หน้ารายละเอียดสินค้า | อ่านรีวิว ดูรูป/วิดีโอ | แสดงสต็อกคงเหลือ, ตัวเลือกสี/ไซซ์ | `frontend/pages/product-detail.html` |
| 4 | หน้ารายละเอียดสินค้า | กดเพิ่มลงตะกร้า | อัปเดตจำนวนในตะกร้าแบบ real-time | `frontend/pages/product-detail.html` |
| 5 | หน้าตะกร้าสินค้า | เลือกใช้คูปอง/โค้ดส่วนลด | คำนวณราคาสุทธิ + ค่าจัดส่งใหม่ทันที | `frontend/pages/cart.html` |

ขั้นตอนที่ 6-9 (ชำระเงิน, ยืนยันคำสั่งซื้อ, ติดตามสถานะ, รีวิวหลังรับสินค้า) จะทำในสัปดาห์ถัดไปเมื่อเชื่อมต่อฐานข้อมูลจริงและระบบชำระเงิน

## Edge Cases ที่รองรับใน Week 1
- สินค้าหมดสต็อก (`stock: 0`) → แสดง badge "สินค้าหมด" บนการ์ดสินค้าและหน้ารายละเอียด ปิดปุ่มสั่งซื้อ
- สินค้าใกล้หมด (`stock <= 5`) → แสดงข้อความเตือน "เหลือสินค้าจำนวนน้อย"
- ค้นหาแล้วไม่พบสินค้า → แสดงข้อความแจ้งแทนหน้าว่างเปล่า
- จำกัดจำนวนที่เพิ่มลงตะกร้าไม่ให้เกิน stock คงเหลือ

## Edge Cases ที่ยังไม่ทำ (รอสัปดาห์ถัดไป)
- สินค้าหมดสต็อกระหว่างลูกค้ากำลังเช็คเอาท์ (ต้อง race-condition handling ฝั่ง DB)
- คูปองหมดอายุ/ใช้ได้เฉพาะสินค้าบางประเภท
- ชำระเงินสำเร็จแต่ระบบสร้างออเดอร์ล้มเหลว (reconciliation)
- คืนสินค้า/คืนเงิน (Return & Refund flow)

## Acceptance Criteria ที่เกี่ยวข้องกับ Week 1
- [x] ราคาที่แสดงในตะกร้าตรงกับราคาสินค้าที่เลือกเสมอ
- [x] ระบบแสดงสต็อกสินค้าให้ผู้ใช้เห็นก่อนกดสั่งซื้อ
- [ ] ระบบล็อกสต็อกสินค้าอย่างน้อย 10-15 นาทีขณะอยู่ในตะกร้า/เช็คเอาท์ (รอ backend จริง)
- [ ] รองรับการชำระเงินอย่างน้อย 3 ช่องทาง (รอสัปดาห์ถัดไป)
- [ ] แจ้งเตือนลูกค้าทุกครั้งที่สถานะพัสดุเปลี่ยนแปลง (รอสัปดาห์ถัดไป)
